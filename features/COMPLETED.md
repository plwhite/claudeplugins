### Move the feature model out of CLAUDE.md into a referenced file [extract-feature-model] — 2026-07-26

Moved the ~120-line feature-model boilerplate out of the project `CLAUDE.md` into a standalone `features/FEATUREMODEL.md`, loaded every session via a Claude Code `@import` (verified live: a headless session with all file-reading tools disabled could quote text present only in the new file), cutting `CLAUDE.md` from 203 to ~90 lines (#43). Repointed the ~10 live references and the precondition checks of all four feature skills (including `feature-end`) to the new location. Rewrote `feature-init` to ship a canonical `FEATUREMODEL.md` alongside its `SKILL.md` and **refresh** the project's copy from it on every run (the master is authoritative; this repo is a plain consumer with no special-casing), replacing the previous embed-the-text-into-CLAUDE.md approach and removing the old hand-synced duplication. `/review-branch` (all four agents, two convergence iterations) caught a bug where a sync-note would have shipped into consumer projects, and prompted the self-refresh design; final user review confirmed.

### Un-pin agent model versions [unpin-agent-model-versions] — 2026-07-26

Replaced pinned, dated `model:` frontmatter ids on four `devproc` review agents with unpinned family aliases, so they track the current default instead of silently running a superseded model (#48): `code-review-architectural.md` moved from `claude-opus-4-6` to `opus`, and `code-review-general.md`/`code-review-nitty.md`/`code-review-simplicity.md` from `claude-sonnet-4-6` to `sonnet`. ### Final sign-off as an explicit sub-task [final-signoff-subtask] — 2026-07-26

Reworked the `devproc` sign-off model so any end-of-feature gate (a final `/review-branch`, a `docs-structure-reviewer` pass, a final user review) is materialised by `/feature-design` as an explicit "Final sign-off criteria" sub-task with one checkbox per gate, instead of living only in `## Sign-off strategy` prose where it was easily skipped or done cursorily (#47). The sub-task is conditional — added only when such gates exist, never as an empty placeholder (settled at spec sign-off against the issue's literal "in every case", to stay consistent with the model's rule that a box which can never be ticked must never be written). Design decision D1 reconciles it with `/feature-end`: a box the close-out step performs itself (the docs review) carries a "(performed at `/feature-end`)" annotation and is the one box legitimately left unticked before close, with `/feature-checkpoint` and the completeness check taught that exception; `/feature-end` was deliberately not expanded to newly run `/review-branch` or originate the user review. Changes span the canonical model (root `CLAUDE.md` and its `feature-init` generator, kept byte-identical), the `/feature-design` and `/feature-end` skills, the `feature-design-reviewer` agent (a new "end-of-feature gates are materialised" check plus an annotation-presence check) and its fixture suite (all five inputs updated to the new baseline plus a new `missing-final-signoff` case, 6/6 passing and independently re-verified), and user-facing docs (`devproc/README.md`, `docs/workflow.md`, `docs/capabilities.md`, the last of which had described the now-removed prose-only shape). Prompt-and-docs-only change; no application code.

### Tidy up internal files that grow without limit [internal-docs-prune] — 2026-07-25

Added prevention rules and a periodic-cleanup tool for the internal, Claude-facing docs (`CLAUDE.md` root and nested, `NOTES.md`, `.claude/rules/*.md`) that grow append-only and dilute their own value (#46). Ships a read-only `internal-docs-reviewer` agent that emits findings tagged with a gating class (`redundant`/`stale`/`judgment`) and an action (`delete`/`move`/`condense`), and a `/internal-docs-prune` skill that applies them by class — auto-applying `redundant`/`stale`, escalating `judgment` (interactive) or deferring it (unattended), and performing moves write-then-verify-then-remove so content is never lost. Prevention rules cap the `CLAUDE.md` `## Current status` section at the in-progress feature plus one recent-completion line (enforced in `/feature-end` and stated in the `feature-init` template). Three findings-contract decisions were settled at code review and drove a re-review to convergence: the reviewer agent is **stateless** with the *skill* owning the settled-`judgment` memory (only the caller sees a decision, so only it can remember it); `redundant` findings are always `delete` (content already at its canonical home); and `judgment`+`move` applies the move on plain confirmation. Documented in `devproc/README.md`, `docs/capabilities.md`, and `docs/workflow.md`, with test fixtures (directory-per-case) under `devproc/tests/internal-docs-reviewer/`. Prompt-and-docs-only change; no application code.

### Add design and spec review agents [spec-design-review-agents] — 2026-07-21

Added two findings-only reviewer agents — `feature-spec-reviewer` (reviews `## Requirements` and `## Sign-off strategy`) and `feature-design-reviewer` (reviews `## Design` and `## Sub-tasks`) — run at the end of `/feature-spec` and `/feature-design`, after the artefact is written but before it reaches the human, so completeness, auditable delivery criteria, and blocking issues are caught first (#20). Each ends with a `READY FOR USER REVIEW` / `NEEDS WORK` verdict and marks every finding `[rewrite]` (the skill fixes it) or `[decision]` (put to the user, never guessed). Both skills gained three modes: reviewed (default, human still signs off), skipped on an explicit instruction, and **unattended** — where a clean verdict stands in for human sign-off, gated strictly on `READY` with no `[decision]` finding, with a skipped review cancelling unattended rather than compounding with it. Every run appends a line to a new `## Review record` plan-file section (including `N/A` when skipped), so an absent line means a stage never ran. Each agent has five committed test fixtures (a clean control plus one per check) under `devproc/tests/<agent>/`, each paired with a recorded `.expected.md`. The reviewers were dog-fooded on this feature's own plan, and the branch review found and fixed two real bugs: the design skill's step-5 template would have silently dropped the spec-stage review record, and its step 6 taught an un-tickable `- [ ] X: none` placeholder box (corrected across the skill, root `CLAUDE.md`, and the `feature-init` template). `README.md`, `docs/workflow.md`, `docs/capabilities.md`, and `dev-process-manager` were updated; the manager's autonomy boundary now selects unattended mode. Prompt/markdown-only change.

### Improve feature subtask flow [subtask-signoff] — 2026-06-25

Added explicit, per-sub-task **sign-off criteria** to the feature workflow so quality steps (testing, docs, code review, user review) become a deliberate up-front choice rather than something quietly skipped. A feature now agrees a **sign-off strategy** at `/feature-spec` (recorded in a new `## Sign-off strategy` plan-file section), `/feature-design` turns it into per-sub-task **checkboxes** the user agrees, and a sub-task is complete only when all its boxes are `[x]` — enforced in `/feature-checkpoint` (records partial state mid-sub-task, never ticks on the user's behalf) and `/feature-end` (won't close with any box outstanding). The canonical model lives in a new `### Sign-off criteria` section of the `feature-init` CLAUDE.md template (synced to this repo's `CLAUDE.md`); the README, `docs/workflow.md`, `docs/capabilities.md`, and the `dev-process-manager` agent were updated to match. Two refinements emerged during the work: the four categories are an open set (a strategy may split one or add a specific sign-off like "agent X confirmed output"), and every criterion must be **auditable** (a clear yes/no at completion). Prompt/markdown-only change, dog-fooded on its own plan. Resolves #25.

### Create dev process manager agent [dev-process-manager] — 2026-06-03

Added a top-level Opus "dev process manager" agent (`devproc/agents/dev-process-manager.md`, run via `claude --agent dev-process-manager` or `claude-run --manager`) that orchestrates the feature workflow: it establishes the feature (creating/starting one if asked), agrees an autonomy boundary with the user, spawns a (normally Sonnet) teammate per sub-task briefed to run `/feature-checkpoint`, reviews the actual changes, shuts each teammate down, and pauses for the user at requirement/design decisions. The container infra gained `claude-run` options `--manager`/`--agent NAME` (with a `dpm` alias) and `--model NAME`, passed through to `run-claude.sh` via `CLAUDE_AGENT`/`CLAUDE_MODEL` on both initial launch and `--continue` relaunch. Testing surfaced that top-level `--agent` does not apply an agent's `model:` to the session, so `claude-run` derives the model from the agent definition and passes `--model` explicitly — keeping the agent file the single source of truth. Resolves #19.

### Fix bugs in container implementation [container-bugs] — 2026-06-01

Fixed three issues in container mode (#17). Automatic login failed because `claude-run` mounted `~/.claude/.credentials` (no `.json`) on both sides — Docker created an empty directory at the missing source and mounted that, so credentials never reached the container; the mount now points at `~/.claude/.credentials.json`. The tmux session was destroyed whenever Claude exited (Claude was the session's top-level process); a new baked-in `run-claude.sh` wraps Claude in a keep-alive loop that auto-relaunches it with `claude --continue` (resuming the conversation), traps SIGINT between runs so Ctrl-C cannot kill the session, and uses a sub-5-second crash-guard to avoid a tight respawn loop — only `claude-stop` now tears the session down. Also documented the Shift-highlight copy/paste tip and corrected the `claude-run` attach hint to print a project path rather than a container name.

### Allow running Claude in a container [claude-container] — 2026-05-28

Added a Docker-based container mode that runs Claude with full ("YOLO") permissions inside an isolated environment. The `docker/` directory contains a Dockerfile (Ubuntu base, Claude Code, python3, tmux) that bakes in the `devproc` plugin and a bypass-permissions `~/.claude/` config; UID/GID are parameterised at build time so files written in the container are owned by the host user. Four wrapper scripts in `bin/` (`claude-build`, `claude-run`, `claude-attach`, `claude-stop`) handle the full container lifecycle; all accept an optional project path and work correctly when symlinked from `/usr/local/bin` or `~/.local/bin`. Credentials are mounted read-only from the host; git identity is passed via env vars; git remote credentials are not passed, limiting Claude to local git operations. Resolves #15.
